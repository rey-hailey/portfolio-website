> 상위 문서: `docs/PRD.md` — 1.4, 3.2 S5, 4.2, 5.5, 6.2, D8(Lab 목록은 사이트 주인 제공)

## 1. 배경 / 목표

- Lab은 직접 만든 것을 눌러보게 해 "직접 만든다"를 증명한다(G5). Lab 목록은 사이트 주인이 따로 준다(D8) → 이 스펙은 화면·필터·상세를 만들고, 콘텐츠가 공개되면 자동으로 채워지게 한다.

## 2. 사용자 스토리

- US-01: 방문자로서 나는 도구·상태로 결과물을 골라 보고 싶다.
- US-02: 방문자로서 나는 상세에서 바로 데모를 눌러보고 제작기 글로 가고 싶다.

## 3. 요구사항

### LAB-R01: 갤러리
- P0 · THE SYSTEM SHALL `/lab`에서 공개된 lab을 order(없으면 최신 발행일) 순 그리드 카드(썸네일+alt, 제목, 한 줄, 도구, 상태)로 보여 주고 상세로 링크한다.
- AC1: 카드 렌더 컨테이너 테스트(제목·한 줄·도구·상태·링크·alt). AC2: draft 샘플은 목록과 라우트에 없다(`/lab/sample-lab` 404).

### LAB-R02: 도구·상태 필터
- P0 · WHEN 사용자가 도구 또는 상태 필터를 고르면, THE SYSTEM SHALL 조건에 맞는 카드만 보여 주고 URL 쿼리(`?tool=&status=`)에 상태를 남기며 결과 수를 `aria-live`로 알린다. JS가 없으면 모든 카드가 보인다.
- AC1: 일치 판단 유틸 단위 테스트(도구만·상태만·둘 다·없음). AC2: 필터 옵션은 공개 lab의 도구 합집합(가나다/알파벳순)과 상태 3종이다(유틸 테스트).

### LAB-R03: 상세
- P0 · THE SYSTEM SHALL `/lab/<slug>`에서 데모 링크(있을 때, 새 창), why, learned, 도구, 제작 기간, 상태, 저장소 링크(있을 때), 공개된 제작기 글 링크(있을 때)를 보여 준다. 본문(MDX)이 있으면 함께 보여 준다.
- AC1: 컨테이너 테스트: demoUrl·repoUrl이 null이면 링크 없음, 있으면 `target="_blank" rel="noopener noreferrer"`. 제작기 링크는 공개된 writing일 때만.

### LAB-R04: 빈 상태
- P0 · WHEN 공개된 lab이 없으면, THE SYSTEM SHALL 필터 없이 빈 상태 문구(`[TODO: 문구]`)를 보여 준다.
- AC1: 현재(`/lab`) 빈 상태 요소가 보이고 카드 0개, 필터 0개 (Playwright).

### LAB-R05: 품질
- P0 · 01 품질 기준(반응형, 제목 순서, Lighthouse 95+, JS 예산)을 지킨다. 필터 스크립트는 공개 lab이 있을 때만 페이지에 실린다.
- AC1: 6개 너비 가로 스크롤 없음, 제목 순서, Lighthouse ≥ 0.95(`/lab`).

## 4. 범위 밖

- 데모 lazy-load 임베드(P1), 승격 표시와 Work 링크(P1), Lab 콘텐츠 자체(사이트 주인 제공), 데모 클릭 GA4 이벤트(10)

## 5. 사이트 주인 검토 대기

1. Lab 결과물 목록을 주시면 관리자 화면(`/keystatic` → Lab)으로 입력하거나 제가 원문으로 옮깁니다. PRD상 1호는 이 사이트입니다.
2. 필터 레이블·빈 상태 문구는 원문이 없어 `[TODO: 문구]`(상태 값 live/experiment/archived는 스키마 값 그대로 표시).
