### 1.1 가져오지 않는 것

- **전화번호** — Artifact 히어로·마무리에 있다. AGENTS.md 6절에 따라 사이트에는 넣지 않는다.
- 보라 accent·IBM Plex·다크 모드·카드 그림자 — 토큰 밖(AGENTS.md 4절).
- Artifact 전체 구성(강점 3부 구조로 페이지를 묶는 것) — 05-work의 케이스 6단계(WRK-R02)를 바꾸는 일이라 이 스펙 범위 밖. 원하면 별도 스펙.

## 2. 사용자 스토리

- US-01: 하이어링 매니저로서 나는 AI 대화 흐름과 기억 구조를 **직접 눌러서** 각 단계가 무엇을 받고 무엇을 내는지 보고 싶다. 왜냐하면 "AI PM"의 설계 깊이를 검증하는 가장 빠른 방법이기 때문이다.
- US-02: 채용 담당자로서 나는 긴 케이스를 내려 읽을 때 지금이 배경인지 결과인지 알고 싶다.
- US-03: 하이어링 매니저로서 나는 도식의 글자를 확대 없이 읽고 싶다(WRR-R04).

## 3. 요구사항 (EARS)

### DGM-R01: 단계 칩

- 우선순위: P0 · 스토리: US-02 · 해결: A1
- 요구사항: THE SYSTEM SHALL 케이스 상세의 각 H2 위에 6단계 칩(배경 · 문제 정의 · 가설 · 실행 · 결과 · 회고)을 두고 현재 단계를 accent로 채운다. 칩은 해당 H2로 가는 링크다. H2 문구·순서(WRK-R02)는 바꾸지 않는다.
- 수용 기준:
  - [x] AC1: 3개 상세의 H2 6개 각각 위에 칩 줄이 있고, 채워진 칩이 그 H2와 같은 이름이다.
  - [x] AC2: 칩 줄은 `nav`(aria-label) 안의 링크이며 현재 칩에 `aria-current="step"`.
  - [x] AC3: WRK-R02 테스트(H2 6개 순서)가 그대로 통과한다(칩은 H2가 아님).
- 검증: Playwright

### DGM-R02: HTML 흐름도 — LAURA 활동 3종

- 우선순위: P0 · 스토리: US-03 · 해결: A2, WRR-R04 AC1
- 요구사항: THE SYSTEM SHALL `activity-flow.webp` 그림을 `Flowchart` 컴포넌트(HTML, 이미지 아님) 3열로 바꾼다. 노드 종류는 공통 뼈대 · 활동별 AI 응답(accent 테두리) · Help(점선, 들여쓰기) · 판단(◇, N/Y 갈래) · 반복 루프 표시. 범례를 둔다. 데스크톱 3열, 768 미만 1열.
- 문구: Artifact "HOW · 대화형 AI" 원문(Role-play · Describe the Scene · Book Quiz 노드 텍스트) 그대로.
- 수용 기준:
  - [x] AC1: `activity-flow.webp`가 렌더 HTML에 없다.
  - [x] AC2: 흐름도 노드 글자가 1440·390 모두 화면상 12px 이상(computed font-size).
  - [x] AC3: 판단 노드의 N/Y 갈래가 텍스트로 있어 스크린리더로 읽힌다.
- 검증: Playwright

### DGM-R03: 인터랙티브 구조도 — Meet the Character

- 우선순위: P0 · 스토리: US-01 · 해결: A3
- 요구사항: THE SYSTEM SHALL LAURA "NEXT · 관계형 AI"에 `SystemDiagram` 컴포넌트를 둔다.
  - 개요 도식(SVG, 3줄 × 4구간: 아이·화면 / 프롬프트 / 저장소 × 대화 시작 / 대화 중 / 대화 끝 / 대화 후)과 "아이가 한 번 말할 때" 확대 도식 2개를 탭으로 전환.
  - 노드(12개)를 누르거나 Enter/Space → 상세 패널에 단계 · 이름 · 줄(lane) · 하는 일 · 들어가는 것 · 나가는 것 · 연결 · 관련 설계 결정 · 프롬프트 이름.
  - 설계 결정 핀 ①–⑤와 아래 목록 ①–⑤가 서로 연결(누르면 해당 노드 선택).
  - "실제 대화 따라가기" 1–4 버튼: 누르면 대화 말풍선과 설명이 나오고 도식에서 해당 노드만 강조(나머지 흐림).
  - 데스크톱(≥1024): 도식 | 고정 패널 2열. 768 미만: 도식 대신 단계 목록 + 아래에서 올라오는 시트(이전/다음 단계 버튼, Esc·바깥 누름으로 닫힘, 닫으면 누른 자리로 포커스 복귀).
  - JS 없으면: 도식과 설계 결정 목록 ①–⑤가 보이고, 패널 자리에 기본 노드("기억이 필요한가?") 설명이 서버 렌더로 나온다.
- 문구·숫자: Artifact 원문(노드 설명 12개, 설계 결정 ①–⑤, 실제 대화 4단계, 베타 결과 4.51 · 4.01 · 약 70% · 116명 353개 · 0건 / 665건, 개선안 29% · 18%, 모델 표기). 현재 본문의 "NEXT · 관계형 AI" 세 문장은 유지하고 그 아래에 둔다.
- 기존 기억 3단계 스트립(memory-1~3)은 "실제 대화 따라가기"와 내용이 같으므로 제거한다.
- 수용 기준:
  - [x] AC1: 노드 클릭·Enter → 패널 제목이 그 노드 이름으로 바뀐다(1440).
  - [x] AC2: 따라가기 3 → `speak · judge · childmem` 노드만 `.hl`, 나머지 흐림.
  - [x] AC3: 390에서 목록 항목 누름 → 시트 열림, "다음 단계"로 이동, Esc로 닫힘 후 포커스 복귀.
  - [x] AC4: 키보드만으로 탭·노드·핀·따라가기 모두 조작 가능, 포커스 링 보임.
  - [x] AC5: 홈 JS(gzip) 30KB 이하 유지(FND-R21). 구조도 스크립트는 LAURA 상세에만 로드.
- 검증: Playwright

### DGM-R04: 벽 표와 As-is → To-be 카드 — ORC

- 우선순위: P1 · 해결: A4, A5
- 요구사항: THE SYSTEM SHALL ORC "문제 정의"의 세 벽 글머리표를 `CauseTable`(벽 / 막혀 있던 것 / 그래서 / 어떻게 넘었나) 표로, "가설"의 목표 그림(`goal-box.webp`)을 `CompareCards`(As-is → To-be, 항목 단계)로, "실행"의 계약 그림(`contract-soc2.webp`)을 세로 `StepList`(OUP 요구 → 역제안 → 합의·인증 취득)로 바꾼다. 768 미만에서 표는 행마다 카드로 쌓이고 각 칸에 열 이름이 붙는다.
- 수용 기준:
  - [x] AC1: `goal-box.webp`·`contract-soc2.webp`가 렌더 HTML에 없다.
  - [x] AC2: 표가 시맨틱 `<table>`(th scope)이고 390에서 가로 스크롤 없음.
- 검증: Playwright

### DGM-R05: 문제 · 원인 · 액션 + 가설→결과 — Sentence Practice

- 우선순위: P1 · 해결: A6
- 요구사항: THE SYSTEM SHALL Sentence Practice의 문제 · 원인 · 액션 글머리표를 3카드로, "가설 → 결과"를 accent 배경 카드(가설 한 문장 + 숫자 3칸: 49.7% → 69.8% · +20.1%p · 다른 활동 +8.4%p의 약 2.4배)로 바꾼다. 개선 전·후 화면(VIS-R03)은 그대로.
- 검증: Playwright

### DGM-R06: 제작 단계 스텝 — LOOL

- 우선순위: P1 · 해결: A7, WRR-R04 AC1
- 요구사항: THE SYSTEM SHALL `production-flow.webp` 그림을 `StepList`(가로, STEP 1–5 · 도구 · 할 일 · 결과물, 직접 만든 툴 단계 강조)와 `CompareCards`(외주로 만들었다면: 작가 · 일러스트 · 성우 · EPUB 4곳 · 수개월 → AI 제작 플로우로: 1명 · 약 2개월)로 바꾼다. LOOL "문제 정의"의 걸림돌 3줄과 "가설"의 해법 3줄은 `CauseTable`(걸림돌 → 해법) 하나로 합쳐 보인다(본문 문장은 그대로 두고 표는 같은 문장을 칸에 담는다).
- 수용 기준:
  - [x] AC1: `production-flow.webp`가 렌더 HTML에 없다.
  - [x] AC2: WRR-R04 AC1이 충족된다(도식 글자 미달 0건).
- 검증: Playwright

### DGM-R07: 리포트 V1 → V2 비교 — LAURA

- 우선순위: P2 · 해결: A8
- 요구사항: THE SYSTEM SHALL "LAURA 리포트"의 아이 · 부모 · 교사 글머리표 위에 `CompareCards`(V1: ✓ 교사 · ✕ 아이 · ✕ 부모 → V2: 아이 · 부모 · 교사 채널별)를 둔다.
- 검증: 수동 확인

### DGM-R08: 공통 품질

- 우선순위: P0
- 요구사항: THE SYSTEM SHALL 새 컴포넌트 모두 디자인 토큰만 쓰고(색 3 + ink 변형, 간격 4px 배수, 폰트 2), 새 npm 의존성 0, 시맨틱 마크업·키보드·포커스·AA 대비·`prefers-reduced-motion`을 지키며, `pnpm build`·`pnpm test`·e2e 전체와 Lighthouse 4항목 0.95를 유지한다. 새 문장은 Artifact 원문 또는 현재 본문에 있는 문자열만 쓴다(Vitest로 원천 문자열 존재 검사).
