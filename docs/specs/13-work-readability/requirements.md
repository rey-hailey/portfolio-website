## 1. 배경 / 목표

### 1.1 배경 — 2026-10-23 화면 점검 결과 (1440·390 전체 캡처)

12-case-visuals로 원본 화면·도식은 들어갔지만, 채용 담당자가 **훑어서 이해하기 어렵다**는 사이트 주인 리뷰가 있었다. 캡처로 확인한 원인은 다음과 같다.

| # | 문제 | 위치 (예) |
|---|------|-----------|
| P1 | 결과가 페이지 맨 아래에 있다. 상단에는 숫자 2개만 있고, "무엇이 문제였고 무엇을 했는지"는 6단계를 다 내려야 보인다. | 3개 상세 모두 |
| P2 | 글자가 많은 도식이 본문 폭(680px)에 갇혀 글자가 읽히지 않는다. 1440 화면에서 오른쪽 절반 가까이가 비어 있다. | LAURA 활동 흐름도, LOOL 제작 흐름, ORC 3단계 레슨 4장 |
| P3 | 앱 화면 비교가 작다. 화면 3장을 680px에 나란히 놓아 한 장이 약 210px다. | LAURA Sentence Practice 개선 전·후 |
| P4 | 캡션 없는 그림이 있어 "무엇을 봐야 하는지"가 없다. | LAURA 실행의 채팅·수준별 답변 FigureGroup, 리포트 점수·교정 |
| P5 | 그림과 그것을 설명하는 글이 떨어져 있다. 원칙 1·2·3 목록 뒤에 그림 2장이 따로 붙는다. | LAURA 실행 |
| P6 | 목록 '추가 사례' 썸네일이 시스템 구조도라, 카드 크기에서 읽을 수 없고 대표 사례보다 시각적으로 무겁다. | /work BRC·OLB 카드 |
| P7 | 한 그림(MemorySteps)이 화면 높이를 넘을 만큼 크고, 정작 중요한 리포트·비교 화면은 작다 — 그림 크기가 중요도와 반대다. | LAURA NEXT |

### 1.2 목표

- 상세 첫 화면(스크롤 없이)에서 **문제 → 한 일 → 결과**와 대표 그림 1장을 본다.
- 모든 도식의 글자를 데스크톱 표시 크기에서 읽을 수 있다.
- 모든 그림에 "무엇을 보여 주는 그림인지" 캡션이 있다.
- 본문 문장은 바꾸지 않는다. 새 문구가 필요한 칸은 `[TODO: 문구]`로 두고 사이트 주인이 채운다(AGENTS.md 7절).

## 2. 사용자 스토리

- US-01: 채용 담당자로서 나는 케이스 상세 첫 화면에서 30초 안에 문제·해결·성과를 파악하고 싶다. 왜냐하면 모든 케이스를 끝까지 읽을 시간이 없기 때문이다.
- US-02: 하이어링 매니저로서 나는 도식과 화면을 확대하지 않고도 읽고 싶다. 왜냐하면 설계의 깊이를 그림으로 검증하기 때문이다.
- US-03: 사이트 주인으로서 나는 덱에서 잘라 온 도식 대신, 웹에 맞게 다시 다듬은 도식(Figma)을 쓰고 싶다.

## 3. 요구사항 (EARS)

### WRR-R01: 상세 상단 30초 요약

- 우선순위: P0 · 스토리: US-01 · 해결: P1
- 요구사항: THE SYSTEM SHALL 케이스 상세의 제목·한 줄 요약 바로 뒤(요약 박스 WRK-R03 앞)에 **문제 / 한 일 / 결과** 3칸 요약을 보여 준다. 각 칸은 해당 케이스 본문의 기존 문장을 그대로 인용하고, 알맞은 원문이 없으면 `[TODO: 문구]`로 둔다.
- 수용 기준:
  - [ ] AC1: 3개 상세 모두 1440×900 첫 화면 안에 요약 3칸이 보인다.
  - [ ] AC2: 요약 문장은 같은 케이스 본문 또는 frontmatter(summary·metrics)에 존재하는 문자열이다(Vitest).
  - [ ] AC3: 본문 H2 6단계 순서(WRK-R02)는 그대로이며 기존 테스트가 통과한다.
- 검증: Vitest(인용 문자열 존재 검사) + Playwright(첫 화면 가시성)

### WRR-R02: 대표 결과 그림을 상단으로

- 우선순위: P1 · 스토리: US-01 · 해결: P1
- 요구사항: WHERE 케이스에 결과 그래프·결과 화면이 있으면, THE SYSTEM SHALL 상단 대표 이미지 자리에 제품 썸네일 대신 또는 함께 결과 그림 1장을 보여 준다. 본문 결과 섹션의 같은 그림은 유지한다.
- 수용 기준:
  - [ ] AC1: LAURA는 월별 활동 완료율 그래프가 상단 요약 영역에 있다.
  - [ ] AC2: 결과 그림이 없는 케이스는 기존 썸네일을 유지한다.
- 검증: Playwright

### WRR-R03: 넓은 그림(브레이크아웃)

- 우선순위: P0 · 스토리: US-02 · 해결: P2·P3
- 요구사항: WHERE 그림이 `wide`로 지정되면, THE SYSTEM SHALL 데스크톱(≥1024px)에서 본문 폭(680px)을 넘어 페이지 폭 토큰(`--container-page`) 안에서 최대 폭으로 보여 주고, 모바일에서는 화면 폭 + 라이트박스로 보여 준다.
- 수용 기준:
  - [ ] AC1: LAURA 활동 흐름도, Sentence Practice 개선 전·후, LOOL 제작 흐름, ORC 3단계 레슨이 `wide`다.
  - [ ] AC2: `wide` 그림이 가로 스크롤을 만들지 않는다(6개 너비).
  - [ ] AC3: 반응형 후보에 실제 표시 폭 2배가 있다(CVS-R14 기준 유지).
  - [ ] AC4: 새 색·간격 값 없음, 새 npm 의존성 0.
- 검증: Playwright(가로 스크롤, 표시 폭) + 수동 확인

### WRR-R04: 도식 글자 가독성 기준

- 우선순위: P0 · 스토리: US-02, US-03 · 해결: P2
- 요구사항: THE SYSTEM SHALL 1440 데스크톱 표시 크기에서 도식 안 본문 글자가 화면상 12px 이상이 되도록 한다. IF 원본 캡처로 기준을 맞출 수 없으면, THEN 사이트 주인이 지정한 Figma 프레임에서 웹용으로 다시 다듬어 내보낸 이미지로 교체한다.
- 수용 기준:
  - [ ] AC1: 도식별 측정표(원본 글자 px × 표시 배율)가 `./design.md` 부록에 있고 모두 12px 이상이다.
  - [ ] AC2: Figma에서 가져온 이미지는 원본 프레임 링크·노드 ID를 design 부록에 기록한다.
  - [ ] AC3: Figma 산출물에도 개인정보(학생 이름·관리자 계정·전화번호)가 없다(CVS-R01 동일 기준).
- 검증: 수동 확인 (측정표 + 스크린샷)

### WRR-R05: 모든 그림에 캡션

- 우선순위: P0 · 스토리: US-01 · 해결: P4
- 요구사항: THE SYSTEM SHALL 케이스 본문의 모든 Figure·FigureGroup·BeforeAfter·MemorySteps·BarCompare에 캡션 또는 제목을 둔다. 캡션은 원본 장표 문구를 쓰고, 없으면 `[TODO: 문구]`로 둔다.
- 수용 기준:
  - [ ] AC1: 렌더 HTML에서 캡션 없는 본문 figure가 0개다(빌드 검사).
- 검증: Vitest 또는 빌드 결과 검사

### WRR-R06: 글-그림 짝 배치

- 우선순위: P1 · 스토리: US-02 · 해결: P5·P7
- 요구사항: WHERE 목록 항목 하나가 그림 하나를 설명하면, THE SYSTEM SHALL 데스크톱에서 그 항목과 그림을 좌우 한 쌍(텍스트 | 그림)으로 보여 주고 모바일에서는 텍스트 → 그림 순으로 쌓는다. 그림 표시 크기는 중요도 순서(결과·비교 > 보조 화면)를 따른다.
- 수용 기준:
  - [ ] AC1: LAURA 실행의 원칙 2(열린 질문)↔채팅 화면, 원칙 3(수준 맞춤)↔수준별 답변이 짝으로 보인다.
  - [ ] AC2: MemorySteps 한 단계 높이가 1440×900 화면 높이의 40%를 넘지 않는다.
  - [ ] AC3: 본문 문장 변경 0(`git diff`에서 문장 문자열 동일).
- 검증: Playwright + 수동 확인

### WRR-R07: 목록 '추가 사례' 카드 정리

- 우선순위: P1 · 스토리: US-01 · 해결: P6
- 요구사항: THE SYSTEM SHALL `/work` 추가 사례 카드 썸네일로 카드 크기에서 읽히는 이미지(제품 화면 또는 Figma에서 다듬은 단순 도식)만 쓰고, 읽을 수 없는 구조도는 펼침(`자세히 보기`) 안으로 옮긴다.
- 수용 기준:
  - [ ] AC1: BRC·OLB 카드 썸네일이 구조도가 아니다. 구조도는 펼침 안에서 라이트박스로 열린다.
  - [ ] AC2: 추가 사례 카드가 대표 사례 카드보다 낮은 시각 위계(작은 썸네일 또는 썸네일 없음)를 가진다.
- 검증: Playwright + 수동 확인

### WRR-R08: 회귀

- 우선순위: P0
- 요구사항: THE SYSTEM SHALL `pnpm build`·`pnpm test`·`pnpm test:e2e`를 통과하고 Lighthouse 4항목 0.95 이상(WRK-R07)을 유지한다.
