## 1. 배경 / 목표

기능과 콘텐츠가 자리 잡은 상태에서, 첫인상과 탐색 경험의 완성도를 높인다. 타이포·섹션 리듬·헤더 거동·카드 상호작용·페이지 전환·케이스 가독성·히어로 수치 연출을 다듬는다. 색·폰트·레이아웃 토큰과 "절제된 톤" 원칙(AGENTS.md 4절)은 유지하고, 모션은 과하지 않게 더한다.

### 1.1 이미 반영되어 이 스펙에서 건드리지 않는 것

직함 라벨(히어로 아이브로), 히어로 숫자·CTA 구성, `word-break: keep-all`, 포인트 색(accent) 정리, `[data-reveal]` 스크롤 진입 방식(transform-only), `prefers-reduced-motion` 대응. 이 스펙은 위를 바꾸지 않고 그 위에 얹는다.

## 2. 사용자 스토리

- US-01: 채용 담당자로서 나는 첫 화면과 각 섹션에서 정돈된 타이포·리듬으로 내용을 빠르게 훑고 싶다.
- US-02: 방문자로서 나는 카드를 가리키고 눌렀을 때 반응과 전환이 매끄러워 탐색이 즐겁길 원한다.
- US-03: 긴 케이스를 읽는 사람으로서 나는 현재 위치와 남은 분량을 알고 싶다.
- US-04: 접근성·저사양·크롤러 환경의 사용자/도구로서 나는 모션이 없어도 모든 정보를 동일하게 얻고 싶다.

## 3. 요구사항 (EARS)

### DSP-R01: 히어로 H1 타이포와 줄바꿈
- 우선순위: P0 · 관련 스토리: US-01
- THE SYSTEM SHALL 히어로 H1에 `letter-spacing: -0.03em`, `font-weight: 700`을 적용한다. WHERE 데스크톱(md 이상)이면 THE SYSTEM SHALL 의미 단위로 수동 줄바꿈한다: `AI 제품을 직접 만들고,` / `그 제품을 해외 B2B 매출로 키운` / `5년 차 PM 손병성입니다.` WHILE 모바일이면 수동 줄바꿈 없이 자동 줄바꿈을 유지한다.
- 수용 기준:
  - [ ] AC1: 데스크톱에서 H1이 지정한 3줄로 끊긴다. 모바일에서는 강제 줄바꿈이 없다.
  - [ ] AC2: 계산된 스타일의 letter-spacing·font-weight가 지정값이다. H1 텍스트(접근성 트리)는 한 문장으로 읽힌다(줄바꿈이 의미를 쪼개지 않는다).

### DSP-R02: 섹션 리듬 — 영문 라벨
- 우선순위: P1 · 관련 스토리: US-01
- THE SYSTEM SHALL 홈 각 주요 섹션 h2 위에 작은 영문 라벨을 둔다(예: `01 · Work`, `02 · Strengths`, `03 · How I Work`, `04 · Career`). 라벨은 토큰(accent·display·small)으로 표시하고 장식 요소는 보조 정보로만 쓴다.
- 수용 기준:
  - [ ] AC1: 지정 섹션에 번호·영문 라벨이 h2 위에 보인다. AC2: 라벨은 제목 구조(h2)를 대체하지 않는다(라벨은 heading이 아니다).

### DSP-R03: 마지막 CTA 섹션 다크 반전
- 우선순위: P1 · 관련 스토리: US-01
- THE SYSTEM SHALL 홈 마지막 CTA 섹션("AI를 제품으로, 제품을 매출로.")만 다크 배경으로 반전한다. 색은 토큰만 쓴다(배경 `--color-ink`, 텍스트 `--color-bg`, 포인트 `--color-accent`).
- 수용 기준:
  - [ ] AC1: 해당 섹션 배경/텍스트가 반전된다. AC2: 반전 영역 텍스트·링크 대비가 WCAG AA 이상(단위 대비 테스트로 확인).

### DSP-R04: 헤더 sticky·블러·스크롤 거동
- 우선순위: P1 · 관련 스토리: US-02
- THE SYSTEM SHALL 헤더를 `sticky` 상단 고정 + 반투명 배경 + `backdrop-filter: blur`로 둔다. WHEN 아래로 스크롤하면 헤더를 숨기고, WHEN 위로 스크롤하면 다시 보인다. IF `prefers-reduced-motion: reduce`이면 THEN 헤더는 항상 보이고(숨김 거동 비활성) 전환은 즉시다.
- 수용 기준:
  - [ ] AC1: 아래로 스크롤 시 헤더가 숨고 위로 스크롤 시 나타난다. AC2: 동작 줄이기에서 헤더는 늘 보인다. AC3: 헤더가 본문 위에 떠도 포커스 이동·키보드 조작이 가려지지 않는다.

### DSP-R05: Work 카드 호버·포커스 효과
- 우선순위: P1 · 관련 스토리: US-02
- WHEN 사용자가 Work 카드에 마우스를 올리거나(hover) 키보드 포커스를 주면, THE SYSTEM SHALL 썸네일 이미지를 `scale(1.04)`로 확대하고(부모 `overflow: hidden`), 제목을 포인트 색으로 바꾸고, 화살표 단서를 드러낸다. 마우스와 키보드 포커스에서 효과가 동일하다.
- 수용 기준:
  - [ ] AC1: hover·focus 양쪽에서 이미지 확대·제목 색·화살표가 나타난다. AC2: 이미지 확대가 카드 밖으로 넘치지 않는다. AC3: 동작 줄이기에서 확대 전환이 즉시(또는 비활성)이고 포커스 표시는 유지된다.

### DSP-R06: Astro View Transitions(썸네일 모핑)
- 우선순위: P1 · 관련 스토리: US-02
- THE SYSTEM SHALL Astro 내장 View Transitions(ClientRouter)로 Work 카드 썸네일 → 케이스 상세 상단 이미지를 모핑시키고, 제목도 이어지게 한다. IF `prefers-reduced-motion: reduce`이면 THEN 모핑 없이 일반 내비게이션으로 동작한다.
- 수용 기준:
  - [ ] AC1: 목록→상세 이동 시 같은 썸네일·제목이 연결 전환된다. AC2: 동작 줄이기·JS 미지원에서 링크가 일반 페이지 이동으로 정상 작동한다. AC3: 추가 클라이언트 JS가 홈 JS 예산(SEO-R06)을 넘기지 않는다(측정).

### DSP-R07: 케이스 상세 — sticky 목차·읽기 진행 바
- 우선순위: P1 · 관련 스토리: US-03
- WHERE 데스크톱이면 THE SYSTEM SHALL 케이스 상세 오른쪽에 sticky 목차를 두고 현재 보고 있는 섹션을 강조하며, 헤더 아래에 읽기 진행 바를 둔다. WHILE 모바일이면 목차를 숨긴다. IF `prefers-reduced-motion: reduce`이면 THEN 진행 바·강조는 즉시 갱신(전환 애니메이션 없음)한다.
- 수용 기준:
  - [ ] AC1: 데스크톱에서 스크롤에 따라 현재 섹션이 목차에서 강조되고 진행 바가 찬다. AC2: 모바일에서 목차가 없다. AC3: 목차 링크 키보드 이동·포커스가 정상이고, 진행 바는 장식(aria-hidden)이다.

### DSP-R08: 히어로 숫자 카운트업
- 우선순위: P2 · 관련 스토리: US-01, US-04
- WHEN 첫 로드 시, THE SYSTEM SHALL 히어로 숫자를 1회, 1초 이내에 카운트업한다. THE SYSTEM SHALL 스크린리더·크롤러에는 최종 숫자가 처음부터 그대로 보이게 한다(애니메이션은 시각 표현에만). IF `prefers-reduced-motion: reduce` 또는 JS 미지원이면 THEN 최종 숫자를 즉시 표시한다.
- 수용 기준:
  - [ ] AC1: 첫 로드에서 숫자가 1초 이내 1회 카운트업 후 최종값에서 멈춘다(반복 없음). AC2: 초기 HTML(크롤러)과 접근성 트리에 최종값이 있다. AC3: 동작 줄이기·JS 끔에서 최종값이 바로 보인다.

### DSP-R09: 모션·라이브러리 제약 (횡단)
- 우선순위: P0 · 관련 스토리: US-04
- THE SYSTEM SHALL 이 스펙의 모든 모션을 `prefers-reduced-motion: reduce`에서 비활성한다. THE SYSTEM SHALL 외부 애니메이션 라이브러리를 추가하지 않는다. 구현은 CSS + 최소 vanilla JS + Astro 내장 기능(ClientRouter)만 쓴다.
- 수용 기준:
  - [ ] AC1: 동작 줄이기에서 R01~R08의 전환·애니메이션이 모두 꺼진다(정보·레이아웃은 동일). AC2: `package.json`에 새 애니메이션 라이브러리 의존성이 없다. AC3: JS 미지원에서 모든 콘텐츠·내비게이션이 작동한다.

## 4. 범위 밖 (Out of scope)

- 1.1의 이미 반영된 항목 변경.
- **보류(사장님 자료 수령 후 별도 스펙):** Work 썸네일 톤 정리, 메인 대표 작업 호버 시 제품 화면 미리보기 — 실제 제품 화면을 받은 뒤 진행.
- 색·폰트·간격 토큰 신규 정의(기존 토큰만 사용). 다크 모드 전역화(마지막 CTA 섹션 반전은 예외).

## 5. 사이트 주인 검토 대기

- 섹션 영문 라벨 문구(예: `Work`, `Strengths`, `How I Work`, `Career`)가 괜찮은지. 바꾸실 라벨이 있으면 알려주세요.
- 다크 반전을 마지막 CTA 섹션 하나로 한정하는 범위가 맞는지.
